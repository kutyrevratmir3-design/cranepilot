# Переносимый комплект весов, 7 ноября 2026

`artifacts/research_bundle_20261107/` содержит небольшую копию выбранных весов,
трёх приводов, калибровок и manifest. Он предназначен для хранения в Git вместе
с кодом. Исходные записи, большие `artifacts/runs` и архивы результатов для
прогноза не нужны. Веса занимают менее 1 МБ. Это комплект исследовательских
прогнозов, не регулятор крана.

Два профиля и три явно задаваемых исследовательских разбиения:

| Разбиение `--fold` | `retained`, профиль по умолчанию | `candidate`, только явно |
|---|---|---|
| `primary` | Три seed модели `phase_space` предыдущего этапа | Три seed нового `adapter_direct8` |
| `short_transfer` | Физический прогноз + LPV actor, ridge .01 | Тот же сохранённый LPV |
| `long_transfer` | Три исходные seed модели `incumbent` | Три seed `latent_residual6` |

Разбиение нельзя автоматически выбирать по текущей длине: это разные наборы
TRAIN/validation/evaluation, а не проверенное правило маршрутизации для
эксплуатации. Параметр `--fold` обязателен. Профиль `candidate` не заменяет
`retained`: primary load MAE выросла примерно с .548625° до .559697°,
превысив допуск 1%. Предупреждение и точное отношение сохранены в manifest
и metadata каждого candidate-прогноза. Улучшения других метрик не отменяют
этот не пройденный критерий принятия.

## Прогноз после клонирования

Из корня проекта создать новое окружение Python3.12 и установить зависимости
из `pyproject.toml`:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -e .
```

Для macOS этот путь выбирает доступный платформенный wheel PyTorch из
требования `torch>=2.6`. Он не переносит Linux-only суффикс `+cpu` из старого
lock-файла. Точные версии проверенного текущего окружения записаны в manifest.
Затем выполнить прогноз:

```sh
PYTHONPATH=src:. .venv/bin/python -m scripts.predict_research_bundle \
  --fold primary \
  --input /absolute/path/history.npz \
  --output /absolute/path/forecast.csv
```

Для нового исследовательского кандидата добавить `--profile candidate`.
Путь к перенесённому комплекту задаётся через `--bundle /absolute/path/bundle`.
Все пути вычисляются относительно каталога модуля либо переданного bundle;
старый путь Windows и пользовательский путь macOS не нужны.

В текущем восстановленном рабочем каталоге тот же запуск доступен через:

```sh
sh handoff/restoration_20261107/main-python.sh \
  -m scripts.predict_research_bundle --fold primary \
  --input /absolute/path/history.npz --output /absolute/path/forecast.csv
```

Этот launcher находится в CraneTransfer, вне корня самого репозитория;
первый пример предназначен для обычного клона. Linux torch `+cpu` из старого
lock-файла не следует механически устанавливать на macOS. Проверенный экспорт
использовал существующее macOS ARM64 Python3.12 окружение; версии записаны
в manifest. Код обучения для применения этих весов запускать не требуется.

NPZ содержит только доступные в момент прогноза входы:

- `theta`: `(N,41)`, радианы, последний доступный отсчёт первым, шаг .01 с;
- `x`: `(N,41)`, метры, тот же порядок;
- `reference`: `(N,41)`, исходный масштаб команд записи;
- `length_m`: `(N,)`, положительная фиксированная длина в метрах;
- `future_reference`: `(N,30)`, известные команды с шагом .05 с, включая
  команду начала прогноза. Первый элемент совпадает с `reference[:,0]`.

`xr` не перекалиброван в напряжение, ускорение или абсолютную цель.
Пустые пакеты, несогласованные формы и неверная начальная команда отклоняются.
Файлы с измеренными будущими `theta/x` не нужны и не используются.

CLI создаёт CSV для семи горизонтов .1/.2/.35/.5/.75/1/1.5 с и соседний
`forecast.metadata.json`. Старые выходные файлы не перезаписываются. Для
нейронных ансамблей есть разброс между тремя seed; это не доверительный
интервал. У единственной LPV модели этот показатель отсутствует.

Python API возвращает все 30 шагов .05–1.5 с:

```python
from scripts.predict_research_bundle import ResearchBundle
import numpy as np

model = ResearchBundle(fold="primary")  # default profile="retained"
with np.load("history.npz", allow_pickle=False) as packet:
    result = model.forecast(packet)
angles = result["prediction_rad"]
acceleration = result["acceleration_m_s2"]
metadata = result["metadata"]
```

## Комплектность и воспроизведение

Каждый входящий файл имеет SHA256. Адаптер и stable residual содержат внутри
полного `state_dict` замороженную базовую сеть; loader не ищет её в прошлых
запусках. Приводы и LPV также загружаются только из bundle. Torch загружается
с `weights_only=True`, LPV NPZ — без pickle.

Manifest фиксирует контрольные суммы исходного кода моделей/наблюдателя/
подготовки входа. Для `.py` CRLF нормализован в LF, поэтому обычная смена
переводов строк при клонировании не ломает проверку. Иное изменение этого
кода намеренно останавливает loader: новая версия требует нового проверенного
экспорта. Метаданные исходных запусков записаны для происхождения весов;
эти пути **не открываются** при inference.

Экспорт из полной локальной исследовательской папки:

```sh
PYTHONPATH=src:. python -m scripts.export_research_bundle --verify \
  --output /absolute/path/new_bundle
```

Этот шаг требует прежних runs и данных, проверяет их сохранённые контрольные
суммы и отказывается заменять существующий каталог. `--verify` сравнивает оба
профиля с прогнозами всех 18 реальных файлов текущей кампании: 36 сравнений,
включая validation, evaluation и load stress. Допуск — .00005°; точный итог
находится в `verification.json`. Текущий комплект проверен на 17 496 пакетах:
все 36 сравнений совпали точно, максимальное расхождение 0°.
После первоначального экспорта была дополнена проверка `result_hashes`
исходных запусков; её отдельное успешное выполнение и неизменность ранее
сравненных файлов зафиксированы в `source_integrity_postexport.json`.
Это дополнительная проверка происхождения, а не новый запуск прогнозов.
Обычному пользователю готового bundle этот
экспорт не нужен.

`tests/test_research_bundle.py` дополнительно переносит реальный комплект
во временный каталог и запрещает чтение любых внешних данных/артефактов
во время загрузки и прогноза всех шести сочетаний fold/profile. Также
проверяются обнаружение повреждённых весов, явный выбор fold, сохранение
предупреждения candidate и игнорирование будущих целевых массивов.

Комплект содержит только выбранные варианты. Отрицательные результаты,
все 72 новых обучения и полные большие массивы остаются в отчёте и локальном
evidence-архиве. Все реальные записи исторически переиспользованы; комплект
не превращает их в новый независимый тест и не доказывает качество управления.
